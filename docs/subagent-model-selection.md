# Subagent Model Selection — Fast Models via EricAI Proxy

Codex spawns subagents (explorer, worker) via the `spawn_agent` tool. By
default, subagents inherit the parent session's model. This document
explains how to configure codex to use fast, cost-efficient models from the
EricAI proxy for subagents.

## How Codex Selects Subagent Models

Codex uses three mechanisms:

1. **LLM-driven per-spawn overrides** — The `spawn_agent` tool exposes
   optional `model`, `reasoning_effort`, and `service_tier` params. The LLM
   explicitly passes these when spawning. Controlled by
   `expose_spawn_agent_model_overrides` (default: `true`).

2. **Role TOMLs** — Role config files in `~/.codex/agents/` pin a specific
   model, reasoning effort, and/or service tier per role. These are
   **locked** — the LLM cannot override them.

3. **Model catalog descriptions** — The `~/.codex/model_catalog.json` file
   (generated by `ericai-proxy/scripts/update_catalog.sh`) provides
   cost-aware descriptions and service tiers that the LLM sees in the
   `spawn_agent` tool schema.

## Configuring Fast Models for Subagents

### Option A: Role TOMLs (recommended — locked per role)

Create TOML files in `~/.codex/agents/`:

```toml
# ~/.codex/agents/explorer.toml
name = "explorer"
description = "Use `explorer` for specific codebase questions..."
model = "gpt-oss-120b"
model_reasoning_effort = "none"
```

```toml
# ~/.codex/agents/worker.toml
name = "worker"
description = "Use for execution and production work..."
model = "Qwen3-Coder-480B"
model_reasoning_effort = "none"
```

Role files are auto-discovered from `~/.codex/agents/*.toml`. The `model`
and `model_reasoning_effort` fields are applied at session start via
`apply_role_to_config()` in `codex-rs/core/src/agent/role.rs`.

### Option B: LLM chooses (default behavior)

With `expose_spawn_agent_model_overrides: true` (the default), the
`spawn_agent` tool description includes the available models with their
cost-aware descriptions:

```
Available model overrides (optional; inherited parent model is preferred):
- `gpt-oss-120b`: gpt-oss-120b — Fast and cost-efficient. Service tiers: priority.
- `glm-5.2`: glm-5.2 — frontier-grade reasoning, deep thinking (slower).
```

The LLM picks `gpt-oss-120b` for lightweight subagent tasks on its own.

### Option C: Hide model overrides from the LLM

If you want to force the LLM to always inherit the parent model (no
per-spawn overrides), set in `~/.codex/config.toml`:

```toml
[features.multi_agent_v2]
expose_spawn_agent_model_overrides = false
hide_spawn_agent_metadata = true
```

## Model Catalog Generation

The `ericai-proxy/scripts/update_catalog.sh` script generates
`~/.codex/model_catalog.json` from the proxy `/v1/models` response. It:

1. Reads the `tags` field from each model
2. Translates tags into cost-aware descriptions (e.g. "Fast and
   cost-efficient" for `fast`-tagged models)
3. Adds `service_tiers: [{id: "priority", name: "Fast"}]` to fast-tagged
   models

The catalog is regenerated on proxy startup and on config.yaml changes.

## Config Reference

| Config | Location | Purpose |
|--------|----------|---------|
| `model_catalog_json` | `~/.codex/config.toml` | Points to the generated catalog |
| `model` | `~/.codex/config.toml` | Main session model (e.g. `glm-5.2`) |
| `model_reasoning_effort` | `~/.codex/config.toml` | Main session effort (e.g. `high`) |
| `service_tier` | `~/.codex/config.toml` | Set to `"default"` (EricAI does not support OpenAI tiers) |
| Role TOMLs | `~/.codex/agents/*.toml` | Per-role model/effort pinning |
| `expose_spawn_agent_model_overrides` | `[features.multi_agent_v2]` | Show/hide model param in spawn_agent |
| `hide_spawn_agent_metadata` | `[features.multi_agent_v2]` | Show/hide agent_type param |

## How Codex Determines "Cheaper" Models

Codex does not reason about dollar costs. It uses catalog metadata:

- **Model descriptions** — Human-readable hints like "Fast and affordable"
  or "Small, fast, and cost-efficient" that the LLM reads.
- **Service tiers** — `priority` (Fast) vs `flex`. Each tier carries a
  description like "1.5x speed, increased usage".
- **Reasoning effort levels** — `none` (non-thinking), `low`, `medium`,
  `high`. Lower effort = faster, cheaper.

The LLM sees all of this in the `spawn_agent` tool schema and chooses
appropriately for the task.
